# 第 4 步 找岗位

## 开头这样讲

- **做什么**：从公开渠道找你现在能投的岗位，整理进跟踪表。只找不投。
- **我们的标准**：真收你这一届（有经验的：符合你年限）、你的身份能做、你能用真事证明得上。招聘原文要求交作品集的岗位默认不列入，你说想留可以关。
- **费不费额度**：脚本抓和统计几乎不费。AI 逐条读招聘全文才费，只读挑出来的那几份。翻网页最费，少用。
- **要不要做、要不要查**：问用户要抓哪些方向、多少家公司。第一次先小量试一个方向。

## 渠道和坑

| 渠道 | 怎么用 | 坑 |
|---|---|---|
| ATS（公司用的招聘系统）的公开接口（Ashby、Greenhouse、Lever） | 最好用，不用登录。用脚本一次拿全部岗位和全文 | 公司代号要猜；同名陷阱；样本偏 AI 公司和独角兽 |
| Simplify 应届和实习列表 https://github.com/SimplifyJobs/New-Grad-Positions | README 能直接下载，有图标标不办签证、要公民、要研究生 | 偏技术，营销内容几乎没有；很多只有标题；含已下架 |
| Workday 补抓 | 广告集团、消费品牌、市场研究公司多用它，要去公司招聘页 | 不补的话，这些方向的数量不可信 |
| 公司官网 | 接口抓不到的公司一家家看 | Apple、Google、Meta 没有公开接口 |
| LinkedIn | 用来找个别岗位，用户自己搜，或连已登录的浏览器慢慢看 | 新版界面最多显示 99+，打开后筛选可能被去掉；数不出岗位数，看不到过去的岗位。只能找，不能统计 |
| Handshake、Wellfound | 要登录，本人登，AI 不输密码 | Handshake 没有按日期筛，看不到过去的岗位 |
| 普通搜索 | 只用来查截止日和应届项目 | 结果常过时，以公司招聘页原文为准 |
| 应届、轮岗、Fellowship 项目 | 搜 “rotational program”“graduate program”“fellowship” 加行业。公开例子：NYT Fellowship、M&T Bank 管理培训生、Brex 轮岗项目 | 名额少，常有固定截止日 |
| 地区站 | Built In 地区站的 entry-level、YC 公司列表 https://www.ycombinator.com/jobs | 公司小，身份信息常不写 |
| 学校就业中心、学校转载的招聘 | 问往届去向，看学校的招聘列表 | 不同大学转载同一条只算一条 |

## 脚本

`scripts/fetch_ats_jobs.py` 只用 Python 标准库，走公开接口，不登录。它不把全文打印到对话，所以很省。

依次试 `python`、`python3`、`py -3`，都没有再讲安装或跳过。人在求职文件夹，脚本用 skill 的绝对路径，输出写进 `资料/`（文件夹会自动建）：

```
python "$HOME/.agents/skills/miao-career/scripts/fetch_ats_jobs.py" --companies stripe,ramp,lever:palantir --keywords "business operations,strategy & operations" --direction 业务运营 --out 资料/岗位-业务运营-2026-11-05.csv
```

有经验的用户再加 `--level experienced --years 3`：不要求标题带新人词；正文要求的年限只要有一个起点超过 3 就不留（“2-4 年”算够得上）；Director、VP、Principal 这类和实习不留，不到 5 年的再去掉 Staff、Sr. Manager。正文没写年限的会留下，投前看原文。

**一个方向一组关键词。** 别用 analyst 这种宽词混多个方向，会把安全岗和商业分析混在一起，数量和门槛都没意义。

Windows 上读写中文文件要明确用 UTF-8，否则可能乱码。

- `--companies-file 文件`：一行一个公司代号
- `--keywords`：逗号分开，默认只看标题。`--keywords-in both` 连正文一起看
- `--location`：默认 `us`；`any` 不限；也可以写 `"chicago|remote"`
- `--fulltext 文件.jsonl`：另存全文，之后只读要看的那一份
- `--direction 方向名`：声明这次是一个方向的样本，才输出机会分
- `--sleep`：请求间隔，最少 2 秒，默认 3 秒。不要改小，也不要同时开好几个跑

**公司代号要猜**：看公司招聘页的网址，`jobs.ashbyhq.com/<代号>`、`boards.greenhouse.io/<代号>`、`job-boards.greenhouse.io/<代号>`、`jobs.lever.co/<代号>`。猜不中就换写法（`doordashusa`、`thenewyorktimes` 这种）。现成的约 120 家在 `data/ats-company-codes.csv`，偏科技，按用户的行业自己补。

**同名陷阱**：同一个代号可能挂的是别的公司。我们查到过 `cursor` 这个代号下挂的不是 Cursor 公司。脚本会打印每家的前 3 个岗位名，看一眼对不对；这只能排除明显不对的，不算确认公司。

**CSV 的列，念给用户时翻成中文**（都是关键词规则筛出的候选，会错，投之前要看原文；空值只表示没读到，不表示不需要或接受）：

| 列 | 中文 |
|---|---|
| `match` | 怎么筛到的。title：标题像新人；body：标题没写，正文年限都不超过 2 年；within_years：年限符合；no_years：正文没写年限 |
| `job_type` | fulltime：写明全职；fulltime_assumed：没写明，推测全职，待核；intern 实习；contract 合同工；part_time 兼职 |
| `max_years_mentioned` | 正文提到的最高年限，“0-2 years” 算 2 |
| `visa_no_sponsor` / `visa_may_sponsor` / `visa_opt_mentioned` | 写了不办签证 / 写了可能办 / 提到 OPT 或 CPT |
| `asks_portfolio` | 提到要交样本，看原文确认后按上面的标准处理 |
| `needs_code` / `needs_cs_degree` / `needs_design_degree` | 提到写代码 / CS 学位 / 设计学位 |
| `mentions_ai` | 提到 AI，公司介绍里出现也算 |

遇到 401、403、429 脚本会停，不要马上重试。

脚本说连不上网时：AI 跑命令的环境可能默认不让联网（【推断】）。让用户批准联网，或者把命令复制到自己的终端跑，再把 CSV 路径告诉你。

## 怎么筛

1. 新人：只要名字带 Associate、New Grad、Early Career、Intern、Rotational 的，或者正文年限都不超过 2 年的（这种另列）。有经验：用脚本的 `--level experienced`，只说“符合你年限的岗位”。
2. 筛选顺序：先确认真收这一届、少经验 → 再确认接受用户的工作授权（需要的话）→ 最后看要求能不能用真事证明。
3. 如果用户在乎 AI：同方向里，正文写 AI 是这份工作或日常要用的先投；只把会用 AI 当要求的其次；没提的照投，不花力气改简历。

## 投前都要核的坑

- 看毕业窗口和入职时间：有的岗位限定毕业时间，暑期实习常要求“实习完还在读”。
- 听起来新潮的头衔（AI 相关、Technologist 这类）常要 4～7 年，打开看。名字叫 Associate 也可能要 1～3 年。
- 合同工和 STEM OPT：常见问题，要向学校和雇主核实（见第 10 步）。
- 有的公司限制每人投递数，要先选。
- 搜索时还在、打开已下架，投前一定再点开。
- 查 H-1B 记录时同名公司多，要核全名（h1bdata.info，每家隔 15 秒以上）。

## 怎么统计

- 只数美国全职应届岗（有经验：符合年限的全职岗），实习另列；同公司同职位不同城市算一个（脚本已合并）；脚本分完再人工看一遍。
- 每个数字写清哪天抓的、样本是什么、没抓到什么。
- “新人口子” = 这类新人岗 ÷ 这类全部岗位。“提 AI”是正文任何地方出现都算，偏高。“不办签证”只算明写的，0% 不等于会办。
- 定向搜和整批抓的口径不同，要分开标。
- 数量分只数全职，写明的 + 推测的都算，输出里分开列。门槛比例的分母是留下的所有行（含实习）+ 因年限被去掉的行，所以两个口径不一样；新人模式下，标题不像新人又要 3 年以上的岗位不进分母。只在加了 `--direction` 时输出，只用于一个方向。

## 整理进跟踪表

从 `assets/job-tracker.csv` 复制成用户的 `投递跟踪表.csv`。每条填：公司、岗位、地点、链接（公司自己的招聘页）、发布日期和截止、为什么适合（对上简历哪一条）、身份信息（写明可办 / H-1B 记录几条 / 写明不办 / E-Verify）、门槛和薪资、优先级（马上投 / 可以投 / 观望）、状态（脚本来的先写“候选（没看原文）”，读过写“已看原文”）。

跑腿和判断分开：抓取用便宜模型或脚本，挑岗位、写“为什么适合”用好模型。

## 交给用户时

先说最该先投的 5 个和原因（不够就有几个说几个；全部不合格就说全部不合格，不凑）；截止最近的放最前；写清第几版、哪天查的；查过但不建议投的也列出来，省得再查；写明这次没做到什么。不点 Apply 之后的提交按钮，不填表。
