# 第 7 步 Networking

这块的来源大多是学校就业中心的公开指南（查阅 2026-11-05）。没有查到各方向靠内推进去多少，也没有查到某个联系人数能保证回复。

## 开头这样讲

- **做什么**：查你学校有什么渠道，列一张名单，排好先找谁，AI 写话术，你自己发。
- **我们的标准**：重点是学习和请教，不开口就要工作。消息要让对方知道“为什么是我”。没回复的请求最多三次（第一封加两次跟进）；对方回复后的联系另算。
- **费不费额度**：写话术很少。查学校渠道要搜索，部分档查 1 所学校就够。翻人最费，优先用 LinkedIn 插件查，别让 AI 翻页。
- **要不要做、要不要查**：先读设置文件。问用户要不要查学校渠道；工具已跳过的不再问。

## 做不到和有风险的（先讲）

- **发消息、加好友**：都由你本人做，AI 不替你做。
- **翻好友列表**：一度好友默认能看，但对方能关。【搜到】https://www.linkedin.com/help/linkedin/answer/a540663 、https://www.linkedin.com/help/linkedin/answer/a545948 二度不能默认能看，看到 “2nd” 不等于能翻完整名单；可以看共同好友，找人介绍。【推断】
- **LinkedIn 协议**禁止用脚本、机器人、浏览器插件等自动访问、抓取资料、加人、发消息，账号有风险。【搜到】https://www.linkedin.com/legal/user-agreement 所以默认：用官方 LinkedIn 插件查人，好友列表你自己翻，看到合适的告诉我。
- **AI 代翻**只有你明确选了才做：先讲清风险，只读，慢慢看（每页隔 15～30 秒），遇验证码就停。
- **邀请有上限**：官方没公布数字，付费也不是无限，触发后通常限制一周。【搜到】https://www.linkedin.com/help/linkedin/answer/a551527
- **Handshake** 条款禁止批量抓取；消息要对方同意才能继续。【搜到】https://joinhandshake.com/legal/tos/
- **校友库**的资格和入口每校不同，我们没进去看过。

## 流程

### 1. 问学校，查渠道（要不要查用户定）

设置文件里没有学校才问。然后查这四样，查到什么写什么，查不到就说：


| 查什么 | 去哪 |
|---|---|
| 校友库、愿意答疑的校友平台 | 学校官网、校友会网站（名字各校不同） |
| 就业中心 | 能不能介绍校友、预约咨询、活动日历 |
| 校友分会 | 地区分会、行业组 |
| Handshake 校友功能 | People 里可以按学校、雇主、角色、毕业年份找学生和校友；岗位页可能有 Alumni at this company。注意 Alumni in similar roles 不一定在这家公司。https://support.joinhandshake.com/hc/en-us/articles/360020974233-Peer-Messaging-in-Handshake |

再问用户已经认识的：亲友、教授、助教、旧上司、社团。这是学校建议的起点。https://www.career.berkeley.edu/start-exploring/informational-interviews/

LinkedIn 学校主页的 Alumni 标签能找校友，但官方说已不支持按年份筛，旧教程的步骤别照搬。https://www.linkedin.com/help/linkedin/answer/a567083/linkedin-page-alumni-section-overview?lang=en 用户也可以自己搜“读过这所学校 + 目标职位名”。

### 2. 建名单

从 `assets/networking-list.csv` 复制成 `networking名单.csv`。基本字段：优先级、姓名、职位、公司、关系、为什么值得联系、资料链接、邮箱、谁介绍的。联系次数只算没回复的请求；最近联系日记你最后一次主动联系的日子。每次联系记日期、聊到什么、下一步、他介绍了谁。字段参考 Harvard：https://careerservices.fas.harvard.edu/resources/harvard-college-guide-to-making-connections-2/

只记公开页面写明的，不猜。邮箱里的往来只当线索，不代表别人同意转交联系方式。不用工具猜别人的工作邮箱。

### 3. 排先后

先按第 2 步的方向分定先找哪行。同一行里的顺序（【推断】综合几所学校的说法）：

1. 已有交集，或明确愿意答疑的人
2. 相关的近期校友、目标岗位上的人
3. 能经共同好友介绍的二度
4. 陌生的相关从业者

想了解工作日常，问实际做这份工作的人；想确认招聘流程，再找招聘的人。不必从最高层开始。

**每周多少人**（可改）：探索期每周 1～2 人；积极求职 5 人一批，按约两周的跟进周期推进，再联系下一批。这是一所学院的建议，不是全美统一标准。https://www.american.edu/sis/career/resources/job-searching-networking.cfm

### 4. AI 写话术，用户自己发

五种话术。每次针对具体的人写，用用户的真事，简短，读起来像真人写的。写完给原文，用户改完自己发。还没联系过的人，先写第一次联系和约聊两种，其余三种到时候再写。用户要全套样板也可以给，标明是样板。

| 话术 | 结构 | 出处 |
|---|---|---|
| 第一次联系 | 简短说明你是谁、和对方的共同点 → 为什么找这个人 → 对行业或机构的兴趣 → 请求信息或建议 → 感谢 | https://alumniandfriends.tufts.edu/advance-your-career/career-networking-mentoring |
| 约 coffee chat | 怎么找到对方 → 介绍自己和在探索什么 → 想请教什么 → 请求 20～30 分钟 | Berkeley，见上 |
| 跟进 | 承接原来的请求，把第一封放在下面方便看；第二次跟进礼貌结束 | American University，见上 |
| 问内推 | 先了解公司和对方的工作 → 表达对公司的兴趣 → 简述相关经历 → 问愿不愿意看简历。合适再谈内推，可以先问公司有没有内推制度；答应后问清要不要先网申、要什么材料、时间 | https://career.berkeley.edu/prepare-for-success/networking/asking-for-a-job-referral/ |
| 见面后感谢 | 感谢时间 → 提到具体收获 → 准备做什么 → 之后有进展再告诉对方 | Tufts，见上 |

内推不是录用保证，也不是每行都有同样的流程。聊完再要内推，别开口就要。

**聊之前准备**：简短自我介绍、具体学习目标、几个问题。这些是第一次聊就够用的东西，用户不需要先有什么成果。

### 5. 跟进节奏

- 从第一封算：约一周没回，跟进一次；约两周，第二次跟进，礼貌结束。之后不再催，转向别人。（Harvard、American University）
- 聊完 1～2 天内感谢；记下收获、没解决的问题、下一步；落实了建议告诉对方。（Berkeley）
- 长期保持联系没有固定间隔，围绕实际进展就行。对方给的时间安排优先。

把“下次跟进日”写进名单。每次打开时提醒到期的。对方说不用了，标“停止联系”，不再联系。

### 6. 定期搜 Gmail（频率用户定）

默认每周一次（这是建议，不是规则）。问用户多久一次，写进设置文件。

如果你有 Gmail 插件，就用下面的语句搜，只读。没有就把语句给用户，让用户自己搜。按用户学校的活动名和发件地址改。这些语句是我们拟的，Gmail 语法来自 https://support.google.com/mail/answer/7190?hl=en

```
校友活动：newer_than:30d {alumni "alumni event" "alumni panel" "regional chapter" mentorship mentor}
招聘会：newer_than:30d {"career fair" "job fair" "employer information session" "employer info session" "employer presentation"}
就业中心：newer_than:30d {"career center" "career services" "career development" "career newsletter" "department newsletter"}
社团和报名：newer_than:30d {networking "coffee chat" "career conversation" "student organization" "professional association" RSVP registration deadline}
已有往来：in:sent {"thank you" "nice meeting" "career conversation" "informational interview"}
```

宽泛词会带来无关邮件，要人工筛。搜到后告诉用户：有什么活动、哪天截止、谁回了信、谁该跟进。不替用户报名，不回信。

**定时**：桌面版 Codex 可以设定时任务，要电脑开着。命令行版没有，改成每次打开时提醒（设置文件记上次搜的日期）。见 `tools.md`。

## 做完

名单和跟进日存好。在设置文件记频率。下次打开先提醒到期的跟进。
