# 第 8 步 投递节奏和跟踪表

## 开头这样讲

- **做什么**：定每周投多少、先投哪些，用一张表记住投了什么，定期看回音。
- **我们的标准**：越早越好，投前再点开确认没下架，每条记清用了哪版简历。跟踪表的格式是通行做法，不是我们研究出来的，觉得麻烦就删列。
- **费不费额度**：很少，不搜索。
- **要不要做**：问用户多久看一次表（默认每周一次）、每周想投多少。

## 节奏

- 越早越好：滚动录取招够就关。一份 2011 年的分析（6,600 个岗位、15 家雇主）说近一半被录用的人是发布第一周内投的，这里只读到二手报道：https://www.biospace.com/apply-early-to-improve-your-chances-of-landing-an-interview 。Ashby 2023 年的平台数据说第一周的申请约是之后每周的 2 倍或更多：https://www.ashbyhq.com/talent-trends-report/reports/2023-trends-report-applications-per-job 。【搜到，数据较旧，只当方向】
- 全年：9～11 月是高峰，12～2 月是淡季，3～4 月第二波。各行业不一样，秋天不能跳过（见第 3 步）。【搜到 + 推断】
- 时间表这样写：先确认够格（毕业时间、年限、身份）；够格的，已经挂很久的这周内投；滚动的，定一个最晚日期；新看到的，发布一周内投；淡季过后再集中找一轮。
- 顺序：截止最近的放最前；同类里按第 2 步的档位先后。
- 有截止日、沾边、身份说得通的，照投，不用纠结。
- 每周投多少：我们没有查到可靠的数字。让用户按自己的时间定，投满约 30 个后看回音再调。

## 投前必查

- [ ] 再点开链接，确认还在
- [ ] 入职时间和毕业时间对得上；实习是不是要求实习完还在读
- [ ] 真实年限要求：正文，不只看标题
- [ ] 正式员工还是合同工
- [ ] 身份要求（需要的话看第 10 步）
- [ ] 这家公司有没有限投数量，要不要先选
- [ ] 用哪版简历

## 申请表

- 表上的题逐条列：必填、选填、填什么。选哪个岗位前先比表上的问题和入职时间。
- 唯一要写的 Why 题：只用真事，挑三件对上岗位描述的事，不编。
- 来源渠道题：如实选。
- 自愿调查（性别、族裔等）可以不透露。
- 工作授权题：拿不准先问学校（第 10 步）。
- **用户自己提交。** AI 可以帮写草稿，不点提交。

## 跟踪表

用 `投递跟踪表.csv`（第 4 步已建，模板在 `assets/job-tracker.csv`）。投递时填：

| 列 | 写什么 |
|---|---|
| 状态 | 候选（没看原文）/ 已看原文 / 想投 / 已投 / 已回复 / 面试中 / offer / 拒了 / 没回 / 已下架 / 投不了 |
| 投递日期 | 哪天投的 |
| 用的简历版本 | 哪一版 |
| 联系人 | 有内推或联系人写谁，和 networking 名单对上 |
| 下次跟进日 | 到期提醒 |
| 回音 | 哪天、什么回音 |

用户投完告诉 AI，AI 更新；或者用户自己改。不想用 CSV，换成 Excel、Notion 都行。

**多久看一次**：用户自己选，写进设置文件。设了定时任务就到时提醒，没有就每次打开时算一下。

看表时说：哪些快截止、哪些该跟进、这周投了几个、回复率多少（没投过写“不适用”，不写 0%）。看完更新设置文件的上次、下次查看日。只说变化，没变化就说没变化，不硬凑。

## 投满约 30 个之后

按方向算回复率，给用户看新旧对比，按第 2 步的规矩决定改不改方向分。回复率低时先看：是简历问题（都没回）还是面试问题（有面试没 offer）。样本还是小，说话要留余地。
